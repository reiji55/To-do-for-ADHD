# Horme

ADHD 向けのタスクアプリ。Phase 0.5（Supabase 接続・永続化）まで実装済み。

「選ばせない・責めない・退出を塞がない」を床として、その日の調子から次の一手を1つだけ出す。

---

## 動かすまで

### 1. Supabase 側の準備

`supabase/schema.sql` を Supabase ダッシュボードの **SQL Editor** に貼って実行する。
`goals` と `inbox_items` の2つのテーブルと、RLS（行レベルセキュリティ）が作られる。

続いて **Authentication → Providers → Email** を開き、以下を確認する。

- Email provider が有効
- **Confirm email** が有効（メールにコードが届くために必要）

さらに **Authentication → Emails → Magic Link** のテンプレートに `{{ .Token }}` が
含まれていること。これが無いと6桁コードがメールに載らない。

```
{{ .Token }}
```

### 2. アプリを動かす

```bash
npm install
npm run dev
```

表示された URL（`http://localhost:5173` など）を開く。

接続先を変えたいときだけ `.env.example` を `.env` にコピーして書き換える。
何もしなければ `src/App.jsx` に書いてあるフォールバック先に繋がる。

### 3. 最初のログイン

1. メールアドレスを入れて「送る」
2. 届いた6桁のコードを入れて「確認する」
3. 「はじめまして」で、仮データを入れるか空から始めるかを選ぶ

一度ログインすればセッションは保持され、次回から認証画面は出ない。

## 構成

```
index.html            アプリの器
src/main.jsx          エントリポイント
src/index.css         土台のCSS（見た目の大半は App.jsx の中）
src/App.jsx           本体。以下の3層に分かれている
supabase/schema.sql   テーブルとRLSの定義
```

`src/App.jsx` の中身は上から順に、

1. **データアクセス層**（`Auth` / `Data`）— Supabase との通信をここに閉じ込めている
2. **選定ロジック**（`selectCandidates` ほか）— どの一手を候補に出すかの判断
3. **画面**（React コンポーネント）

次の段階でオフライン対応（IndexedDB）を足すときは、1 の中身だけを差し替えれば済む。
画面側は `Data.*` しか呼んでいない。

## 設計のメモ

### 次の一手 ＝ 工程の未完了の先頭

`process_steps` の未完了の先頭が「次の一手」。別々のデータとして持たない。
工程が空なら、次の一手を書いた瞬間にそれが1件目になる。

工程を主役にしないための歯止め：

- 一階層のみ（工程の中に工程は作らない）
- 0個でもいい（登録を強制しない）
- Focus には工程を出さない（出るのは次の一手ひとつだけ）
- 育ちすぎたら詳細画面から独立した目標に昇格させる

### 容量（エネルギー）は目標が持つ

「取り掛かるのに必要なエネルギー」を軽／中／重で目標に付ける。
調子（快調／平常／低調）は「どの目標に向かうか」を選ぶための足切りに使う。

低調の日に重い目標は出さない。失敗と恥を生むだけなので。

### 声

事実だけを短く。評価も励ましも絵文字もなし。
不可逆な変化（完了・捕獲・手放し）のときにだけ出す。候補を1枚送るのは無言。

### 開発用パネル

画面の外に出ている検証用の操作。`src/App.jsx` の先頭にある

```js
const DEV_TOOLS = true;
```

を `false` にすると丸ごと消える。本番ではこちら。

## Supabase の鍵について

`anon key` は公開前提の鍵で、リポジトリに含まれていても問題ない。
RLS が有効なので、この鍵だけでは他人の行には触れられない。

**`service_role` キーは絶対にリポジトリへ置かないこと。** RLS を貫通する。
